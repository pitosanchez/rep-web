# Is there a real, citable ZIP-level healthcare-access data source for the Bronx?

**Status:** Researched 2026-08-31
**Question driving this doc:** Can any published, methodologically-documented dataset replace `weight_res` (a HUD/USPS ZIP‑to‑Tract *population* weight, not a healthcare measure) in the `careAccess` / "Access Constraint Proxy" MapLibre layer at `where-we-live-site/lib/mapLayers.config.ts` / `where-we-live-site/app/api/geo/bronx-zips/route.ts`?

## Executive Summary

No. None of the four candidate families of federal, state, or city healthcare-access data is a direct drop-in replacement for `weight_res` — a real, continuous, ZIP-level, published-methodology measure of healthcare access for the Bronx's 104xx ZIP codes does not exist as a ready-made dataset from any agency. HRSA's Health Professional Shortage Area (HPSA) program is the only candidate with a genuine, publicly documented *access* methodology (population-to-provider ratio, poverty, travel time to nearest source of care), and Bronx does have several currently-designated Primary Care HPSAs — but HPSA geography is drawn as irregular shortage-area polygons (whole counties, sub-county "population group" service areas, or individual facilities), not ZIP codes or census tracts, and the score is a categorical 0–25/0–26 index, not a rate comparable cleanly across arbitrary ZIP boundaries. CMS's NPPES NPI Registry and the CMS Provider Data Catalog ("Doctors and Clinicians") both publish real provider point-location data with ZIP codes and specialty (taxonomy) codes and could be aggregated by hand into a provider-per-ZIP or provider-per-population count for the Bronx — but that requires building your own pipeline (filter to NY, filter to 104xx ZIPs, geocode/count, divide by population), not consuming a published per-ZIP file. NYC DOHMH's Community Health Profiles and the UHF neighborhood system publish at Community District / UHF geographies (both are ZIP-code *aggregates*, with an official ZIP→UHF crosswalk), not raw ZIP level, and their published 50+ measures are general population-health indicators, not a dedicated care-access index. No federal or state agency publishes a drive-time-to-specialist or nephrology-specific access dataset that covers the Bronx at ZIP or tract granularity — HRSA's Area Health Resources File (AHRF) is county-level only (all of the Bronx is one county, so it yields a single data point for the whole borough) and contains no travel-time variable. The best realistic path is either (a) keep the current proxy but re-label/caveat it more precisely, or (b) invest in a custom pipeline built from NPPES/CMS provider point data aggregated to ZIP and normalized by population — which is engineering work, not a data source that exists today.

## Candidates Evaluated

### 1. HRSA Health Professional Shortage Area (HPSA) designations

- **Source name / agency:** Health Professional Shortage Area (HPSA) Program, published by HRSA's Bureau of Health Workforce (BHW), Division of Policy and Shortage Designation (DPSD).
- **Granularity actually available:** HPSAs are **not** published at ZIP or census-tract granularity as a rule. A designation is one of three types — (1) **Geographic Area** (can be a whole county, a partial county, or another civil division depending on state rules), (2) **Population Group** (a subgroup, e.g. Medicaid-eligible or low-income residents, within a defined area boundary), or (3) **Facility** (a single clinic/hospital/correctional facility). Each designation is stored as an **irregular polygon** (confirmed directly against HRSA's own ArcGIS feature service, `https://gisportal.hrsa.gov/server/rest/services/BHW/HPSA/MapServer/0`, whose Primary Care HPSA layer (`HPSA_PC`) is `esriGeometryPolygon`, not a ZIP or tract layer). The downloadable HPSA data files do carry a "Common ZIP Code" and "HPSA Component Postal Code" field plus a GEOID field (which can reference a county, county subdivision, or census tract depending on the record) — but these describe the address/anchor of the designation record, not a systematic ZIP-code tiling of the shortage area's boundary, so they cannot be used to reliably assign a score to every Bronx ZIP.
- **Methodology citation:** `https://bhw.hrsa.gov/workforce-shortage-areas/shortage-designation/scoring` (HRSA BHW, "Scoring Shortage Designations" — page fetched via Wayback Machine snapshot `https://web.archive.org/web/20260825101821/https://bhw.hrsa.gov/workforce-shortage-areas/shortage-designation/scoring` because the live page blocks automated fetches; content is HRSA's own). It documents, in HRSA's own words:
  - **Primary Care HPSA score, 0–25**: Population-to-Provider Ratio (10 pts), % population below 100% FPL (5 pts), Infant Health Index/IMR or LBW (5 pts), Travel time to nearest source of care outside the HPSA (5 pts).
  - **Dental Health HPSA score, 0–26**: Population-to-Provider Ratio (10), % below FPL (10), water fluoridation status (1), travel time to NSC (5).
  - **Mental Health HPSA score, 0–25**: Population-to-Provider Ratio (7), % below FPL (5), elderly ratio (3), youth ratio (3), alcohol/substance abuse prevalence (1+1), travel time to NSC (5).
  - MUA/P uses a separate Index of Medical Underservice (IMU), 0–100, with designation at IMU ≤ 62.0.
  - This is a genuinely documented, primary-source scoring methodology — the best-documented of the four candidates.
- **Bronx coverage:** Confirmed live via HRSA's own GIS feature service query (`.../MapServer/0/query?where=HPSAName LIKE '%Bronx%'` and neighborhood-name queries against `HPSA_PC`, run 2026‑08‑31) — the Bronx has multiple currently-**Designated** Primary Care HPSAs of type "Medicaid Eligible Population HPSA," e.g. `ME - Northeast Bronx` (HPSAID 1361731127, score 18) and `ME - High Bridge` (HPSAID 1366401437, score 18). These match named Bronx service areas also referenced by New York State's own Regents-designated Physician Shortage Area list for Bronx County (High Bridge, Hunts Point/Mott Haven, Morrisania service areas) — see `https://www.nysed.gov/sites/default/files/2026-regents-physician-shortage-area-booklet-final.pdf`. Data vintage: live/current as queried August 2026; HRSA states dashboard/download data is updated daily/quarterly.
- **Access mechanism:** Web tools (HPSA Find, Data Explorer) at `https://data.hrsa.gov/topics/health-workforce/shortage-areas`; downloadable XLSX/CSV/SHP files at `https://data.hrsa.gov/data/download`; a public ArcGIS REST feature service at `https://gisportal.hrsa.gov/server/rest/services/BHW/HPSA/MapServer` (no key required, queried directly for this research).
- **Verdict for this use:** Not a drop-in replacement. It is the only candidate with a genuine, HRSA-documented healthcare-access methodology, and Bronx is covered, but the geography is shortage-area polygons (not ZIP/tract) and the score is a bounded categorical index (0–25/0–26), not a continuous per-ZIP rate. Using it would require your own point-in-polygon aggregation (assign each Bronx ZIP's centroid or overlap area to a HPSA polygon, some ZIPs might span multiple or zero designated polygons) and a decision about how to handle ZIPs with no overlapping HPSA (would they get "no shortage" or "no data"?).

### 2. CMS provider location data — NPPES NPI Registry & CMS Provider Data Catalog ("Doctors and Clinicians" / Care Compare)

- **Source name / agency:** National Plan and Provider Enumeration System (NPPES) NPI Registry, and the "Doctors and Clinicians" national file in the CMS Provider Data Catalog (Care Compare's underlying public data), both published by the Centers for Medicare & Medicaid Services (CMS).
- **Granularity actually available:** **Point-level** (one row per provider enrollment/address), not pre-aggregated to ZIP. Confirmed directly from CMS's own documents:
  - The NPPES "Data Dissemination File - Readme" (downloaded and parsed directly, `https://www.cms.gov/regulations-and-guidance/administrative-simplification/nationalprovidentstand/downloads/data_dissemination_file-readme.pdf`) lists fields including `Provider Business Practice Location Address Postal Code`, `Provider Business Mailing Address Postal Code`, and up to 15 `Healthcare Provider Taxonomy Code_n` / `Healthcare Provider Primary Taxonomy Switch_n` fields (specialty codes) per NPI.
  - The CMS Provider Data Catalog "Doctors and Clinicians" (DOC) Data Dictionary (downloaded and parsed directly, `https://data.cms.gov/provider-data/sites/default/files/data_dictionaries/DOC_Data_Dictionary.pdf`) confirms a `zip` field ("Group or individual's ZIP code (9 digits when available)") plus `Primary specialty` and up to four secondary-specialty fields, at one row per clinician/enrollment/address.
  - Provider specialty is drawn from NUCC's official Health Care Provider Taxonomy code set (published by the National Uniform Claim Committee, `https://www.nucc.org/`), which does include a specific Nephrology code (`207RN0300X`, Internal Medicine > Nephrology, confirmed against NUCC's published taxonomy documents), so specialty-specific filtering (e.g., isolating nephrologists) is possible in principle.
  - **No ZIP-level provider-density or provider-to-population-ratio file is published by CMS.** You would have to download the full national file, filter to New York State and Bronx 104xx ZIPs, and compute counts/densities yourself.
- **Methodology citation:** NPPES readme — `https://www.cms.gov/regulations-and-guidance/administrative-simplification/nationalprovidentstand/downloads/data_dissemination_file-readme.pdf`; CMS Provider Data Catalog DOC Data Dictionary — `https://data.cms.gov/provider-data/sites/default/files/data_dictionaries/DOC_Data_Dictionary.pdf`; taxonomy code standard — `https://www.nucc.org/images/stories/PDF/taxonomy_24_0.pdf` (NUCC Health Care Provider Taxonomy, v24.0).
- **Bronx coverage:** Yes — NPPES and the CMS DOC file are national and include every enrolled provider's practice ZIP code, so Bronx 104xx ZIPs are inherently covered; no special extract exists for Bronx specifically. Vintage: NPPES publishes a full monthly replacement file (current file as of this research dated August 10, 2026 per `https://download.cms.gov/nppes/NPI_Files.html`) plus weekly incremental updates.
- **Access mechanism:** Public downloadable files, no authentication — NPPES bulk file at `https://download.cms.gov/nppes/NPI_Files.html` (>1 GB monthly ZIP); individual lookups via the NPPES NPI Registry web tool/API at `https://npiregistry.cms.hhs.gov/`; CMS Provider Data Catalog files/API at `https://data.cms.gov/provider-data/`.
- **Verdict for this use:** Real, ZIP-tagged, specialty-filterable, Bronx-covered, and re-downloadable on a schedule — the strongest *raw material* of the four candidates — but it is **not a published per-ZIP access metric**. It requires a genuine ETL step: download, filter to Bronx ZIPs, count/aggregate (optionally by specialty, e.g. nephrology via taxonomy `207RN0300X`), and normalize by population (e.g., via Census ACS ZCTA population) to produce a rate. That is buildable and would be a legitimate, citable replacement for `weight_res` once built, but it does not exist today as a downloadable "Bronx ZIP care-access score."

### 3. NYC DOHMH facility/clinic data and Community Health Profiles

- **Source name / agency:** NYC Department of Health and Mental Hygiene (DOHMH) — the "New York City Community Health Profiles" publication, and DOHMH's United Hospital Fund (UHF) neighborhood geography system.
- **Granularity actually available:** **Community District**, not ZIP. Confirmed directly from the DOHMH page itself (`https://www.nyc.gov/site/doh/data/data-publications/profiles.page`, fetched and parsed): "The New York City Community Health Profiles capture the health of **59 community districts** across the city. They contain over 50 measures of neighborhood health." The Bronx is divided into a subset of those 59 community districts. Separately, DOHMH also maintains the **UHF34/UHF42** neighborhood scheme, which the agency's own documentation describes as "aggregations of zip codes" built for health-survey statistical power (`https://a816-dohbesp.nyc.gov/IndicatorPublic/data-stories/geographies/`, fetched directly) — and DOHMH publishes an official ZIP(ZCTA)-to-UHF crosswalk file (`uhf-to-zip crosswalk.csv`, in DOHMH's own GitHub org, `https://github.com/nychealth/coronavirus-data/blob/master/Geography-resources/UHF_resources/uhf-to-zip%20crosswalk.csv`). So a defined many-ZIPs-to-one-UHF mapping exists and is publicly documented, but no DOHMH publication reports care-access measures at raw single-ZIP resolution — UHF and Community District are both *coarser, many-ZIP roll-ups*, and going from a UHF/CD-level statistic back down to a single ZIP would mean assigning every ZIP in that UHF/CD the same value (a real accuracy loss, not a genuine ZIP-level measure).
- **Methodology citation:** `https://www.nyc.gov/site/doh/data/data-publications/profiles.page` (geography and content description); `https://a816-dohbesp.nyc.gov/IndicatorPublic/data-stories/geographies/` (UHF/ZIP relationship, explicitly DOHMH-authored); no dedicated "Community Health Profiles technical methodology PDF" was found — the profiles page is DOHMH's own documentation of scope but is largely a data-navigation page, not a statistical-methods document.
- **Bronx coverage:** Yes, Bronx community districts and Bronx UHF neighborhoods are both covered (e.g. the South Bronx UHF34 neighborhood combines the UHF42 areas of Highbridge-Morrisania, Crotona-Tremont, and Hunts Point-Mott Haven, per DOHMH's own geography documentation).
- **Access mechanism:** Interactive web tool only for the profiles themselves (`https://a816-health.nyc.gov/hdi/profiles/`), with a "Community Health Profiles Public Use Dataset (Excel)" download linked from the profiles page; geography crosswalk files are openly downloadable from DOHMH's GitHub org (no auth).
- **Verdict for this use:** Not usable at ZIP granularity as published. Even setting geography aside, the Community Health Profiles' 50+ measures are general population-health indicators (chronic disease prevalence, behavioral risk factors, social determinants), not a dedicated care-access/provider-availability index — no specific "primary-care access" or "provider density" measure was confirmed in the profiles' page-level description available to this research. Would require both a coarser-than-desired geography (UHF or Community District rolled down to ZIP) and confirming a genuinely access-related measure exists in the underlying spreadsheet.

### 4. Drive-time / distance-to-specialist-care datasets (federal/state)

- **Source name / agency checked:** HRSA's Area Health Resources File (AHRF) — HRSA Bureau of Health Workforce, National Center for Health Workforce Analysis (NCHWA); Appalachian Regional Commission (ARC) "Access to Care" travel-time studies; USDA ERS food/access datasets (checked for methodology parallels only).
- **Granularity actually available:** AHRF is explicitly **county-level, state-level, and national-level only**. Confirmed directly from HRSA's own AHRF Clinician Dashboard definitions document (downloaded and parsed, `https://data.hrsa.gov/Content/Documents/topics/AHRF%20Definition.pdf`): "The Area Health Resources Files (AHRF) Clinician Dashboard provides **county- and state-level** counts and provider-to-population ratios of selected health professions." Because Bronx County is coextensive with the borough of the Bronx, AHRF would yield exactly **one data point for the entire Bronx** — no sub-county or ZIP variation at all. No travel-time or drive-time variable is present in AHRF's documented content (its inputs are AMA/ADA licensure files, CMS NPI counts, and Census population data — no geospatial travel-time computation). ARC's "Access in Appalachia" travel-time pilot study (`https://www.arc.gov/wp-content/uploads/2024/12/Access-in-Appalachia-Pilot-Study-October-2024.pdf`) is county-level and, per ARC's own scope, covers only the 423 counties of the federally defined Appalachian Region — **Bronx County, NY is not in the ARC region** and is not covered by that study at all.
- **Methodology citation:** `https://data.hrsa.gov/Content/Documents/topics/AHRF%20Definition.pdf` (HRSA AHRF Clinician Dashboard Definitions, updated January 2026 — confirms county/state-only geography, data sources, and the absence of a travel-time variable); `https://www.arc.gov/wp-content/uploads/2024/12/Access-in-Appalachia-Pilot-Study-October-2024.pdf` (ARC's own scope statement, confirming it is Appalachian-region-only).
- **Bronx coverage:** AHRF — yes, but only as a single county-wide figure with no internal ZIP/tract structure. ARC — no, out of scope entirely (Bronx is not part of the Appalachian Region).
- **Access mechanism:** AHRF data files downloadable from `https://data.hrsa.gov/data/download` (select "Health Workforce" → AHRF); no API found. ARC study is a static published PDF report, not a downloadable geocoded dataset.
- **Verdict for this use:** Not usable. No federal or state agency was found publishing a drive-time-to-specialist or nephrology-specific access dataset at Bronx ZIP or tract granularity. AHRF is real and citable but too coarse by construction (county = whole borough), and has no travel-time content despite the original hypothesis. ARC does not cover the Bronx at all.

## Recommendation

**No single published dataset is a direct drop-in replacement for `weight_res`.** None of the four candidates offers a real, continuous, ZIP-level (or cleanly tract-aggregable-to-ZIP-level) numeric measure of healthcare access for Bronx ZIP codes, backed by a published methodology, ready to consume as-is.

Ranked by how close each comes, and what it would take to actually use it:

1. **Best raw material, most work: NPPES / CMS "Doctors and Clinicians" provider point data.** This is the only candidate with (a) a real, machine-readable, ZIP-tagged, specialty-filterable, monthly-refreshed national dataset and (b) full Bronx coverage by construction. To turn it into a `careAccess`-style layer you would need to: download the national NPPES file (or the smaller CMS Provider Data Catalog "Doctors and Clinicians" file, which already limits to Medicare-enrolled clinicians and is far smaller than the >1GB full NPPES file), filter records to `Provider Business Practice Location Address Postal Code` in the Bronx 104xx range (or to New York State and then spatially clip to Bronx), optionally filter by taxonomy code for a specific specialty (e.g. `207RN0300X` for nephrology), count providers per ZIP, and normalize by ZIP population (e.g., Census ACS 5-year ZCTA population estimates, a separate but well-documented Census Bureau source) to get a rate like "providers per 10,000 residents." This is a legitimate, citable methodology once built — but it is engineering + a defined methodology write-up, not a data source you can point `weight_res` at today. Estimated effort: a small ETL script plus a one-time or periodically-refreshed static JSON, similar in shape to the existing `bronx_zip_to_tracts.json` pipeline.

2. **Best documented access-specific methodology, wrong geography: HRSA HPSA.** If the team wants an *access-specific*, agency-scored measure rather than a raw provider count, HPSA is the only candidate with HRSA's own documented scoring rubric (population-to-provider ratio + poverty + infant health/travel time, 0–25 scale) and confirmed active Bronx designations. Using it for a ZIP map would require a one-time GIS step: pull the HPSA polygon shapefiles (`https://data.hrsa.gov/data/download`, "Shortage Areas"), overlay Bronx ZIP boundaries (e.g., NYC's MODZCTA shapefile, already referenced by DOHMH's GitHub geography resources), and assign each ZIP the score of whichever HPSA polygon(s) it overlaps (with a defined rule for ZIPs spanning multiple polygons or none). This trades "genuine access methodology" for "categorical/bucketed rather than continuous" and "requires custom polygon-to-ZIP aggregation you must document and defend."

3. **Not usable without dropping to coarser geography: NYC DOHMH Community Health Profiles / UHF.** Only usable if the project is willing to accept Community-District- or UHF-level granularity (each covering multiple ZIPs) rather than true per-ZIP variation, and even then no confirmed dedicated care-access measure was found in the profiles' publicly described content — would need manual inspection of the "Community Health Profiles Public Use Dataset (Excel)" to confirm whether a usable measure exists at all.

4. **Not usable: AHRF / drive-time datasets.** AHRF is too coarse (Bronx = 1 county = 1 value) and has no travel-time content; ARC doesn't cover the Bronx.

**Concrete next step if the team wants to proceed:** treat option 1 (NPPES/CMS provider-point aggregation, optionally normalized by Census ZCTA population, optionally weighted or cross-checked against HPSA designation for Bronx ZIPs) as the real engineering task, and update the layer's `description`/`is_approximate` metadata to describe *that* methodology once built, rather than expecting to find an existing per-ZIP file to swap in.
